## 可泛化经验

1. `SegmentReduceGrad` 的 Host 不是无条件占满全部 AIV，而是按数据量右移阈值估算 `block_dim`。小数据算子需要权衡核数、每核工作量和启动/标量控制开销。
2. Kernel 对循环内重复同步可在外层分配 `TEventID`，循环结束释放；但具体硬件流水组合仍须实测，不能假设一定更快。
3. 多个算子显式声明 `KERNEL_TYPE_AIV_ONLY`，并大量使用按 tiling key 分支的专用几何；这种专用必须依据通用 shape/dtype 属性，不能匹配公开样例。
4. 任务切分普遍使用数据块阈值、整除对齐和比例区间，而不是机械地“一个元素/小片段一个任务”。

## Concat 实验结果

- V3 原策略：尽量覆盖 40 核，公开用例官方脚本中位数 10.17 μs。
- 采用 16 KiB 输入数据/目标核的切分阈值后，公开用例自然形成 9 个任务（每个输入一个任务），三次独立官方运行为 8.70、8.92、8.84 μs，中位数 8.84 μs。
- 循环外复用 MTE2/MTE3 硬事件 ID：10.3605 μs，拒绝。
- 把最终 Block Dim 强制压到估算出的 4 核：11.710 μs，拒绝。
- 单批次时跳过 task 除法/取模：8.82 μs，未稳定优于 8.70 μs 版本，拒绝。

最终只保留“按数据量控制行批次数”这一项，因为它同时满足通用性、正确性和稳定收益。
