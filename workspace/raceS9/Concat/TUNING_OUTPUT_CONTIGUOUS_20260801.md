# Concat 连续输出区间优化记录（2026-08-01）

## 结论

本版新增 tiling key 3：按连续输出地址区间切核。它不是为公开的小型非对齐 Case1 定制，
而是补足旧实现面对“大张量、多输入、32B 对齐段”时 MTE3 命令过碎、核间负载不均的问题。

最终版本在 Ascend 910B4（dav-2201）/ CANN 8.5 上：

- 官方原始 Case1：8.6095 us，精度和性能通过；
- 固定种子的泛化回归：1000/1000 全部通过；
- 检查的输出数据：43,357,777 字节；
- 正式提交包已从 ZIP 全新解压、安装并再次通过官方 Case1；
- ZIP SHA256：`703c69d03bca8b17d378b2a8d9165c7c3fd37bb757fab712a7385201e9b46862`。

## 算法

稳定版按输入张量划分任务。新路径把输出看成
`outer * outputAxis * inner` 的连续元素流，在 32B 边界上分给多个 AIV。
每个核读取与自身输出区间相交的若干输入片段，在同一个 UB tile 中连续拼接，
再用一次连续 MTE3 写回。各核只写互不重叠的 GM 区间。

启用条件：

- 输入数量不超过 128；
- 每个输入在一条 output row 中的 segment bytes 都是 32B 的整数倍；
- `dim == 0`，或总输出不小于 1 MiB。

非对齐、小型非 dim0、输入数超过 128 等情况继续走已经验证的旧路径。

核数策略：

- `outer == 1`：约 64 KiB 输出/核；
- `outer > 1`：约 8 KiB 输出/核；
- blockDim 不超过可用 AIV 数量。

## 被拒绝的实验

曾尝试把连续输出路径统一改成 `TQueBind<VECIN, VECOUT, 2>` 双缓冲：

- 9 MiB、两个大输入：19.94 -> 18.30 us，有收益；
- 512 KiB：7.08 -> 7.48 us，退化；
- 128 个 8 KiB 输入：7.44 -> 7.58 us，退化；
- 128 个 64 KiB 输入：26.74 -> 28.42 us，退化。

因此没有把双缓冲作为统一路径保留。后续若单独增加 tiling key，应只在输入很少、
且每核至少能连续处理约 3--4 个 tile 时启用，并重新做隐藏形状风格的泛化回归。
