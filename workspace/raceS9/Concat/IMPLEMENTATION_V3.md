# Concat V3：通用多行二维 DMA

## 版本结论

运行环境为 CANN 8.5、Ascend 910B4。V3 已通过官方用例与 8 组扩展回归。官方测试连续调用 30 次，最终全新安装包测得中位数 10.17 μs；同步正确但逐片搬运的 V2 为 17.4705 μs，V3 提升约 41.8%。

## 瓶颈与改法

公开输入包含 128 行和 9 个切片。V2 为每个 `(outer, input)` 发起一次搬入、一次搬出和两次跨流水事件同步，总计 1152 个小任务。小切片下，DMA 启动、地址计算和同步开销远大于实际 64 KiB 数据搬运。

V3 把同一个输入的多行合并成二维 DMA：

1. Host 计算每行连续片段字节数 `axisSize × inner × sizeof(T)`。
2. 根据 64 KiB tile 上限得到 UB 可容纳的行数。
3. 根据可用核心数限制每任务行数，使总任务数仍能覆盖约 40 个 Vector Core。
4. Kernel 用一次二维 `DataCopyPad` 把若干源行紧凑搬入 UB，再用带目标行间距的二维 `DataCopyPad` 写回拼接输出。
5. 当单行片段超过 UB 时，走逐行分块的正确性回退。

该路径只依赖 dtype、shape、UB 容量和核心数，适用于任意合法拼接轴，不含公开 shape 或 split 序列判断。

## 正确同步

GM→UB 使用 MTE2，UB→GM 使用 MTE3。二者之间分别通过 `MTE2_MTE3` 和 `MTE3_MTE2` 硬事件建立依赖。早期仅使用同流水 `PipeBarrier` 的版本会读到尚未搬完的数据，虽然性能较快但结果错误，不能保留。

## 回归范围

`tests/regression_v3.py` 共 8 组，全部逐元素精确等于 `torch.cat`：

- 官方 `float16 [128,256]` 几何；
- `float32` 首轴非对齐；
- `int32` 中间轴；
- `int8` 末轴非对齐；
- 四维负轴；
- 零长度输入切片；
- 单行片段大于 64 KiB 的回退路径；
- 64 个输入且含大量空切片。

## Profiling 摘要

最终用例 `Block Dim = 40`。稳定调用的调度耗时约 9–11 μs；AIV 指标主要落在 scalar 地址/任务控制与 MTE2，说明下一阶段应减少 per-task 标量控制，或尝试双缓冲重叠，而不是增加 Vector 计算。
